## Context

项目使用 uni-app 开发微信小程序，主包体积限制为 2MB。当前项目中存在大量重复的 CSS 声明，这些重复代码增加了主包体积。`common.scss` 已经提供了丰富的工具类，但未被充分利用。

### 当前状态

- **全局样式文件**：
  - `src/uni.scss`：定义 SCSS 变量和主题色
  - `src/styles/common.scss`：提供全局工具类和通用样式
  - `src/styles/mixins.scss`：提供 SCSS mixins

- **全局样式覆盖范围**：
  - 布局类：`.flex`, `.flex-center`, `.flex-middle`, `.flex-between` 等
  - 间距类：`.m-*`, `.p-*`, `.mt-*`, `.mb-*` 等（10rpx 的倍数）
  - 字体类：`.fs-*`（14-40rpx），`.c-*`（颜色）
  - 圆角类：`.br-*`（4-20rpx）
  - 文本类：`.text-center`, `.text-left`, `.ellipsis` 等
  - 按钮类：`.primary-btn` 及其变体

- **问题**：
  - 页面和组件中重复声明了 `padding: 20rpx`, `margin: 20rpx` 等
  - 重复声明了 `font-size: 28rpx`, `30rpx`, `34rpx` 等
  - 重复声明了 `border-radius: 10rpx`, `20rpx` 等
  - 重复声明了 `color: #333`, `#666` 等
  - 重复声明了 `text-align: center` 等

## Goals / Non-Goals

### Goals

- 减少主包体积（CSS 部分）
- 提高样式代码复用率
- 统一样式使用规范
- 保持现有样式表现不变

### Non-Goals

- 不改变现有 UI 表现
- 不重构全局样式架构
- 不引入新的 CSS 框架或工具
- 不优化非 CSS 相关的代码

## Decisions

### Decision 1: 优先使用全局工具类

**决策**：优先使用 `common.scss` 中已有的工具类，通过 class 组合实现样式。

**理由**：
- 全局工具类已经在项目中定义，无需额外代码
- class 组合比内联样式更易维护
- 减少重复代码，降低主包体积

**示例**：
```vue
<!-- 之前 -->
<view class="item" style="padding: 20rpx; margin: 20rpx; text-align: center;">
  
<!-- 之后 -->
<view class="item p-20 m-20 text-center">
```

### Decision 2: 保留必要的局部样式

**决策**：对于以下情况，在页面/组件中保留样式声明：
1. `common.scss` 中没有对应的工具类
2. 样式是组件/页面特有的，不适合全局化
3. 样式需要动态计算或依赖组件状态
4. 样式使用了复杂的嵌套或伪元素

**理由**：
- 避免过度抽象，保持代码可读性
- 某些样式确实需要局部作用域
- 动态样式无法用静态 class 实现

**示例**：
```scss
// 保留：组件特有的复杂样式
.component-specific {
  &::before {
    content: '';
    // 复杂的伪元素样式
  }
}
```

### Decision 3: 补充常用但缺失的工具类（可选）

**决策**：如果发现某些样式模式在多处重复使用，但 `common.scss` 中没有对应工具类，可以考虑补充。

**理由**：
- 提高复用率
- 统一样式规范

**注意事项**：
- 需要评估使用频率，避免过度设计
- 新增工具类需要验证不影响现有样式

## Risks / Trade-offs

### 风险

1. **样式表现不一致**
   - **风险**：替换为工具类后可能出现细微差异
   - **缓解**：全面测试，逐页验证

2. **可读性下降**
   - **风险**：过多的 class 组合可能降低代码可读性
   - **缓解**：保持合理的 class 数量，必要时保留局部样式

3. **维护成本**
   - **风险**：需要同步更新多个文件的 class
   - **缓解**：建立规范，未来开发遵循复用原则

### 权衡

- **代码体积 vs 可读性**：优先减少体积，但保持可读性
- **全局样式 vs 局部样式**：优先全局，但保留必要的局部样式
- **一次性优化 vs 渐进式优化**：建议按模块分批优化，降低风险

## Migration Plan

### 阶段 1：分析与准备（1-2 天）
1. 扫描所有 Vue 文件，识别重复模式
2. 对比全局样式，确认可复用类
3. 制定替换规则

### 阶段 2：补充全局样式（如需要，1 天）
1. 分析常用但缺失的样式
2. 补充到 `common.scss`
3. 验证不影响现有样式

### 阶段 3：分批优化（3-5 天）
1. 优先优化主包页面（`src/pages/`）
2. 优化公共组件（`src/components/`）
3. 优化业务模块组件
4. 每批优化后进行测试

### 阶段 4：验证与收尾（1-2 天）
1. 全面测试所有页面
2. 检查主包体积变化
3. 修复发现的问题

### 回滚计划

如果出现严重问题：
1. 使用 Git 回滚到优化前的版本
2. 分析问题原因
3. 调整优化策略后重新实施
